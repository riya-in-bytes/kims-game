## Project

Kim's Game: a memory/observation game, Android-first, built on Expo SDK 58 (React Native 0.88, React 19, TypeScript, Expo Router with typed routes). Phase 1 uses emoji items; the code is structured to add image packs and new modes later.

## Commands

Package manager is **npm** (`package-lock.json`, no `bun.lock`). Node 22 via `.nvmrc`.

```bash
npx expo start                 # dev server
npx tsc --noEmit               # typecheck
npx expo lint                  # lint (eslint-config-expo, flat config)
node scripts/gen-tones.mjs     # regenerate assets/sounds/*.wav (synthesized, not hand-made)
```

There is no test runner yet. The game logic is written so it can be tested: reducers and scoring are pure, and the RNG can be injected (`Rng = () => number`).

Native Android build (no Android Studio; `android/` is gitignored and generated by CNG):

```bash
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
npx expo run:android --variant release   # unsigned APK -> android/app/build/outputs/apk/release/
```

For Play Store builds, use `npx eas-cli@latest build --platform android` (it handles signing and produces an AAB).

## Architecture

Imports use the `@/` alias for `src/`.

**Game core (`src/game/`) is pure TS with no React Native imports, apart from the `useReducer` wrappers.**
- `types.ts`: `GameItem` (a discriminated union on `kind`: `'emoji' | 'image'`), `ItemPack`, `LevelConfig`, `Round`, and `ModeDefinition`.
- A mode (`modes/*.ts`) is just data plus two functions: `levelFor(level) → LevelConfig` (the difficulty curve) and `buildRound(config, pack, rng) → Round`. `answerSource` (`'board' | 'choices'`) controls whether the player picks from the re-shown tray or from a separate choices tray. Register new modes in `MODES` in `modes/index.ts`. Engine, screens and storage are all mode-agnostic.
- `difficulty.ts` `configFor()` sits between a mode and a round: it applies the Relaxed/Normal/Hard multipliers and caps the distractor count by how many items the pack holds. Always build rounds through `configFor`, never by calling `mode.levelFor` directly.
- Two state machines share the same phase vocabulary (`study → hidden → answer → result`):
  - `engine.ts` (`useGame`): solo endless play with 3 lives. A perfect round goes up a level; game over restarts at level 1.
  - `match.ts` (`useMatch`): pass-and-play for 2–4 players over `MATCH_ROUNDS` rounds. All players get the same `Round`, and a `handoff` phase sits between turns. The reducer is built once per match on purpose, so a settings change mid-match does not rebuild it.
- `scoring.ts`: `scoreRound` produces a `RoundResult` (hits, false picks, misses, perfect, points).

**Timing (`src/hooks/`).** `usePhaseTimer` is the single source of truth for remaining study time. The countdown bar and the timeout both read from it. It is pausable and pauses automatically when the app is backgrounded. `useRoundTimers` wraps it to drive study → hidden (auto-dispatch `HIDE`) → answer (after `COVER_MS`). Solo and party screens both use it, so phase-timing changes go here, not in the screens.

**UI.** `src/app/play/[mode].tsx` (solo) and `src/app/party.tsx` (pass-and-play) are thin wrappers around the shared `components/RoundView.tsx`, which renders every phase. `ItemVisual` is where each `GameItem.kind` is rendered; a new item kind needs a branch there. Design tokens (colours, spacing, type scale) live in `theme/tokens.ts`. The app is dark-only (`userInterfaceStyle: "dark"`).

**Settings and persistence.**
- `SettingsProvider` loads settings from AsyncStorage and **renders nothing until they load**, so a game never starts on the wrong difficulty.
- `storage/progress.ts` keeps stats per difficulty and per mode under the key `kims-game:progress:v2`, and migrates v1 (which becomes the Normal difficulty).
- Saves are serialized through a promise queue to avoid read-modify-write races. `applyRound` is the pure fold of one round into the stats.
- If you change the stored shape, bump the key and add a migration.

**Feedback.** `feedback/useFeedback.ts` plays sounds (expo-audio, with players created lazily as module singletons) and haptics, gated by settings. Failures are swallowed on purpose so sound problems never break gameplay.
